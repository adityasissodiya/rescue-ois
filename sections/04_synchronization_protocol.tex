\subsection{Journal and Replication (M2, M3)}
\label{sec:protocol-m2}
\label{sec:protocol-m3}

Only the command edge assigns positions to decisions, so its journal has one total
order. It accepts each \textit{client\_event\_id} once and assigns \textit{event\_seq}
atomically with the journal insert; a duplicate folds onto its existing entry. Consumers
replay the journal in \textit{event\_seq} order, so materialized state is rebuildable
from it. Responder edges reach the journal through a transactional
outbox~\cite{richardson2018microservices}: a field submission is accepted only once it is
stored locally, and marked forwarded only once the command edge acknowledges it or
recognizes a duplicate. Delivery is at least once and deduplicated at the command edge,
with no order across responders before it. The command edge forwards its journal to the
core the same way, so the core holds a prefix. These are standard mechanisms; any
eventually consistent replication, a CRDT included, could replace them.

\subsection{Fenced Promotion and the Lease (M4)}
\label{sec:protocol-m4}

M4 is where the prototype implements policy S1. There is no autonomous failover: an
operator decides that command moves, and M4 keeps the core's journal single-writer
across the move.

\textit{Epochs and the holder check.} The regional core issues each command tenure an
epoch, per incident, which gives promotions on independent vehicles a single order. The
epoch is a fencing token in the usual sense~\cite{kleppmann2017ddia}, as in view numbers
and Zab epochs~\cite{oki1988viewstamped,junqueira2011zab}. Every journal entry carries
its epoch, and the core accepts forwarded entries only from the node recorded as holding
the current epoch. Checking the node, not only the number, matters because a demoted edge
that reconnects can read the current epoch from the core. The check binds authority to a
node, which is the conflation the model removes (\S~\ref{sec:model-gap}).

\textit{Promotion.} The operator first confirms that the old command edge is
unreachable. The candidate copies the journal prefix held by the core and verifies that
it is contiguous; the core issues the next epoch, and its insert orders concurrent
attempts; only then does the role change. Promotion therefore needs the candidate to
reach the core, but it does not wait for the old command edge.

\textit{The lease.} A cut-off former command edge cannot learn that its epoch is stale,
so it must stop by itself. Write authority is a lease~\cite{gray1989leases} renewed at
the core, on traffic and on an idle heartbeat. A command edge that has not reached the
core for the lease length $L$ stops accepting decisions: on a timer, not on being told.

\textit{What S1 gives up.} In Figure~\ref{fig:promotion-timeline}, B takes authority at
once while A accepts until its lease lapses, so for up to $L$ both edges accept
decisions: S1 keeps (a) for $L$ and (b) as soon as B reaches the core, and gives up (c)
at the edges. The core's journal still never takes entries from two holders, and the
refused edge demotes itself and raises an operator alert. What A accepted but never
forwarded stays on A: decisions from its legitimate tenure (X) as well as from the
overlap (Z). Neither is merged, so the record is incomplete until someone reviews them.

\textit{The lease as a policy parameter.} The same lease stops a legitimate command edge
that has lost only its backhaul, so $L$ sets where S1 sits in the trade-off of
\S~\ref{sec:tradeoff}. A longer lease keeps decisions flowing through longer outages; a
shorter one narrows the window in which two edges accept. The prototype uses $L=90$\,s by
default, a value with no operational grounding. In the model, the corresponding
parameters are $L$ under S2 and $T$, $T'$ under S4, and they are the organization's to
choose (\S~\ref{sec:policies}).
