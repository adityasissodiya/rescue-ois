In rescue-service incident response, one principal holds operational command authority at every moment, yet responders must keep working through responder-side and backhaul partitions. Authority-bearing decisions must therefore stay attributable to that single commander even under intermittent connectivity. Standard distributed-systems tools do not fit this setting. Consensus moves the writer to whatever quorum is reachable, and conflict-free replicated data type (CRDT) merge is mergeable-by-default. Neither lets an operator designate the authoritative writer under partition. We present \methodname{} (AAL), a consistency discipline. AAL places the incident-journal linearization point at the edge node that currently holds command authority, so authority-bearing writes serialize at that node. Non-authority data (reference state, field submissions, materialized views) stays locally available and is forwarded later, and command transfer uses fenced promotion rather than leader election. We specify and verify AAL using TLA+ and Hypothesis and implement it in a prototype built around responder outboxes, a single incident journal, and fenced promotion. We evaluate it under tc-netem emulated partitions against a Hanssen-style CRDT-LWW baseline and a Raft consensus baseline. The evaluation confirms the gap concretely: CRDT merge cannot encode authority for non-commutative decisions, and Raft moves the writer to the reachable quorum rather than the designated commander. Under AAL, partitions on either responder or backhaul links do not block command-edge progress. A fenced promotion's protocol cost is single-digit milliseconds; by design, wall-clock time is dominated by the operator's confirmation. The cost is no automatic failover.
