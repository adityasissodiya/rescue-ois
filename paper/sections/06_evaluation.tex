\section{Evaluation}

\subsection{Pilot Setup}

Describe the drill setup in enough detail that another group could reproduce the evaluation:
\begin{itemize}
  \item number of vehicles, tablets, and portable mesh relays;
  \item deployment environment and incident scenario;
  \item partition injection method for WAN and mesh failures;
  \item software build or configuration baseline used during the pilot.
\end{itemize}

\subsection{Metrics}

The evaluation should center on operationally meaningful measurements rather than generic system benchmarks:
\begin{itemize}
  \item incident bootstrap latency;
  \item field edit end-to-end propagation time;
  \item partition recovery time;
  \item sustained offline usability duration;
  \item data staleness under partition;
  \item command-promotion latency.
\end{itemize}

\subsection{Results and Failure Modes}

Do not separate success results from failure observations too aggressively. For a systems paper in this area, the most credible evaluation combines measured performance with the edge cases that appeared during drills. If a polling interval, stale manifest, duplicate forward, or promotion handoff created problems, report it plainly.
