Evaluation forthcoming, see Phase 2. The NCA evaluation will replace the current structural validation text with emulation measurements from the unified \texttt{eval\_metrics.jsonl} harness. These will be emulation measurements with explicitly stated injected latencies, useful for relative comparisons between protocol variants and partition profiles, not for absolute field-performance claims.

The planned scenario set covers bootstrap latency versus incident size, field-edit propagation versus queue depth, recovery time versus partition duration, promotion latency, command-edge throughput, and scaling with concurrent responder vehicles. Each scenario cell will report at least 30 runs, median, p95, and interquartile range.

The evaluation will also include a safety-property subsection. The primary path is a TLA+ model with a \texttt{NoTwoWriters} invariant over the single-writer plus manual-promotion model; the secondary path is a Hypothesis test corpus over generated partition, promotion, replay, and commit schedules. The baseline subsection will compare Rescue OIS against at least an analytical Raft, multi-primary, and CRDT design table, with a measured Raft baseline if the planned hashicorp/raft glue is complete in time.
