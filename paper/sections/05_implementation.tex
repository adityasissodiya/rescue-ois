\section{Prototype Implementation}
\label{sec:implementation}

The repository contains a prototype service path for the core and edge tiers, plus deployment scaffolding for the target vehicle environment. Python services target Python~3.12 and use FastAPI, Pydantic models, asyncpg, and uvicorn. Database schemas are managed through numbered SQL migrations. Docker Compose files instantiate the emulated core, command edge, and responder edges used in Section~\ref{sec:validation}; a separate \path{baseline/crdt} Compose stack provides the CRDT-LWW comparison point. The evaluated path is narrower than the full target deployment. The \textit{sync-api} provides a synthetic incident bootstrap endpoint and accepts incident-journal backfill. The edge \textit{ops-api} persists field submissions into \textit{outbox.device\_outbox} with \textit{client\_event\_id} idempotency. The \textit{syncd} responder path forwards unacknowledged outbox entries to the command edge; the command-edge \textit{syncd} path assigns \textit{event\_seq} inside a database transaction and deduplicates duplicate \textit{client\_event\_id} values. The command-to-core forwarder backfills committed incident-journal entries to the core. These are the paths exercised by the evaluation.

Authentication in the target deployment is layered: a VPN overlay protects vehicle-to-core traffic, Nginx terminates TLS/mTLS and passes certificate-derived identity to backend services, and tablets authenticate to their local vehicle using enrolled certificates. In the reported emulation these controls are deployment design, not measured mechanisms: traffic uses plain HTTP on a Docker bridge network and the Python tablet stub supplies synthetic device and user identifiers.
