\section{System Architecture}

\subsection{Design Principles}

The system is built around five principles:
\begin{itemize}
  \item \textbf{Offline-first:} all previously synchronized data remains available without connectivity.
  \item \textbf{Single incident writer:} exactly one command node sequences and commits incident events.
  \item \textbf{Forward-only edits:} tablets and responder vehicles enqueue edits locally and forward them upstream.
  \item \textbf{Mesh as transit only:} the wireless mesh carries traffic between edge nodes, but does not expose user VLANs end to end.
  \item \textbf{Existing identity:} the deployment integrates with the authority's established identity and certificate infrastructure.
\end{itemize}

\subsection{Tier 1: Regional Core}

The regional core hosts the authoritative master-data platform. It runs PostgreSQL~16 with PostGIS~3.5 (SRID~3006, SWEREF~99~TM), a publication pipeline that stages, validates, and promotes geodata into versioned offline packages, and a tile-serving stack (Martin for vector tiles, GeoServer for WMS/WFS). An Nginx reverse proxy terminates TLS and routes API traffic to internal microservices. A WireGuard hub on a \texttt{10.252.0.0/24} overlay connects all enrolled vehicles. Feed importers ingest external data from SMHI, Trafikverket, Lantm\"ateriet, and Naturv\r{a}rdsverket. Published packages consist of PMTiles bundles, compressed attachment archives, and SHA-256-signed manifests that edge nodes pull over HTTP range requests.

\subsection{Tier 2: Vehicle Edge}

The vehicle edge tier is the architectural center of the paper. Each vehicle carries the same edge hardware profile, but nodes operate in one of two software roles:
\begin{itemize}
  \item \textbf{Command vehicle:} commits incident events, assigns sequence numbers, materializes incident state, and backhauls to core when WAN is present.
  \item \textbf{Responder vehicle:} caches master data, serves local tablets, and queues field edits in an outbox until they can be forwarded to command.
\end{itemize}

This role split is intentional. It preserves hardware interchangeability while keeping the incident journal under one authority-bearing node at any time. Any responder can be promoted to command by configuration and operational procedure.

\subsection{Tier 3: Field Tablets}

Field tablets are leaf clients attached to a local vehicle only. They use an encrypted local database and local tile cache, and they communicate over HTTPS with the edge node in their vehicle. Tablets have no direct mesh participation and no direct internet dependency. This sharply limits the exposed trust and connectivity surface.

\subsection{Network Segmentation}

Each vehicle carries a Teltonika RUTX50 router that enforces a five-VLAN segmentation model keyed on a per-vehicle identifier. VLAN~10 (Management, \texttt{/27}) is reserved for device administration. VLAN~20 (Edge Services, \texttt{/27}) hosts the K430 compute node and its containerized services. VLAN~30 (Operational Tablets, \texttt{/26}) carries tablet traffic and permits only outbound HTTPS to the Edge Services zone. VLAN~40 (Sensors, \texttt{/27}) isolates drone feeds and environmental sensors. VLAN~50 (Maintenance, \texttt{/27}) provides technician access. Firewall rules enforce strict zone isolation: tablets reach only the local \texttt{ops-api} endpoint over port~443, and no user VLAN is extended across the Rajant mesh. The mesh operates as a Layer~3 transit fabric on \texttt{10.253.0.0/16}, carrying only application-layer traffic between K430 nodes. This design prevents broadcast storms, limits the attack surface, and ensures that a compromised tablet cannot reach other vehicles or the wider mesh.
