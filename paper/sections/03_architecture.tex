\subsection{State Classes and Consistency Contracts}
\label{sec:state-taxonomy}

AAL does not apply one consistency model to all data. The single-writer
rule applies only to authority-bearing incident-journal entries.
This split is a RedBlue-style~\cite{li2012redblue} consistency partition with
authority-bearing decisions in the strong set and forward-only field
submissions, cached reference data, and materialized state in the weaker
classes. Table~\ref{tab:state-contracts} summarizes the main state classes.

Master and reference data are owned by the regional core and cached at edges.
Their partition behavior is stale-but-available local read.
Field submissions are durable at the responder first. They become authoritative
only after command acceptance. Authority-bearing incident events are sequenced
by the command edge with a command-assigned \textit{event\_seq}.
Materialized state is derived from the append-only incident journal.

Artifacts and attachments use immutable or manifest-based distribution. Audit
records and command-to-core backhaul are forwarded eventually. Promotion and
fencing metadata are part of the command-authority protocol. The current
evidence for promotion/fencing is model-level; Section~\ref{sec:sync} gives the
protocol rule.

\subsection{Tiered Edge Topology}

The architecture follows from these constraints. The regional core provides
master/reference data and receives backhaul. Vehicle edges provide local
services during disconnection. Responder vehicles queue submissions durably. The
command edge owns the append-only incident journal. Tablets are leaf clients and
do not participate directly in command sequencing.

The mesh is transit, not the consistency mechanism. User VLANs are not extended
across vehicles. Application services communicate between edge nodes over routed
links in the target deployment.
